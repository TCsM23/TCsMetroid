How it works

From sketch to playable map

TCsMetroid treats a Metroidvania map as a graph. Rooms are nodes, doors are edges, and each door has a rule saying which power-ups open it.

Design

Drag rooms on a grid and draw doors between them. Give each door a rule such as J | (D & G): "Double Jump, or Dash and Grapple together".

Invent power-ups

Every map has its own power-up list. Give each one a letter, a name and a colour. Abilities open doors; collectibles only raise max energy in the game.

Verify

The checker proves the boss can be reached, the route finder compares four search algorithms, and the analysis page finds rooms that can trap the player.

Play

Press Play to explore the map yourself. The game uses the same rules, so a door that's locked in the checker is locked in the game too.

Algorithms inside

  • ParserRecursive descent turns door rules into expression trees
  • BFSFixed-point check groups rooms into spheres of progress
  • Dijkstra · A*Fastest route over (room, power-ups held) states
  • KahnTopological sort gives the order power-ups must be found
  • TarjanStrongly connected parts split by one-way drops
  • Union-findRegions a player can walk around freely
  • Reverse BFSSoft-lock states the game warns you about
  • Fisher–YatesSeeded shuffles for the randomizer
